# Writing reusable skills

A skill describes a repeatable task, the inputs it needs, and how to verify its output.

## Structure

- Give the skill a short name and a description of the tasks that should trigger it.
- State required inputs, dependencies, and limits before the procedure.
- Write ordered steps with observable outcomes.
- Keep detailed examples in referenced files and link them from the main instructions.
- Store repeatable operations in scripts when that improves consistency.

## Review

Check that a reader can identify when to use the skill, supply its inputs, follow
its steps, and verify the result without relying on unstated project knowledge.
Use placeholders in examples and exclude credentials and deployment-specific data.
